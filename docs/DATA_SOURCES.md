# RPL data-source decision register (M0)

Updated 2026-10-20. This is a **public documentation and terms review**, not a provider contract or an authenticated API coverage test. Every source stays **UNAPPROVED**; automatic ingestion/training remains disabled. Provider terms can change.

The strictly local, fail-closed [multi-source empirical accuracy protocol](M0_SOURCE_ACCURACY_PROTOCOL.md) implements field-specific matched official-reference comparisons, Wilson uncertainty and independent-upstream warnings. It does **not** yet contain empirical RPL source observations or activate an ingestion pipeline.

## Owner's $0-only source strategy (binding, 2026-10-19)

**No purchases, paid subscriptions, paid historical files, API overages, paid account upgrades, credit-card billing, paid-hosting fallback, or trial-to-paid conversion.** A future provider's premium-only RPL dataset is **unavailable**, not a reason to change tiers. Retain the current Free/Hobby hosting limits. API registration is eligible only if the exact intended operation is permanently priced at $0 within permitted quotas, with no required payment details or unexpected charges. If nothing lawfully usable covers a feature, show an honest "data unavailable" state; never fabricate it.

Every currently identified free, openly published or manual corroboration candidate is in the machine-readable **[18-source ranking registry](M0_FREE_SOURCE_REGISTRY.json)**. The catalog has `priority` **1-4**, `zeroCost` classification, role(s), source terms and known quality warnings. All `active=false` at M0, meaning **no provider integrations or model training** have been enabled. Adding a source requires documenting its exact free access and legal scope; the CI policy tests reject paid/unknown tiers and invented measured error rates. An article readable without charge may be **manual citation only**, not a free bulk API.

**RPL official-domain extraction restriction (reviewed 2026-10-20):** [the RPL's own website](https://premierliga.ru/) explicitly states that *automated extraction of information from the site by any services is prohibited without the RPL's official permission*. Its original match reports are valuable **for manually reviewing/citing individual formal decisions**, not a licensed bot/CSV feed. Never infer crawler permission from public access, an official URL, a browser's ability to display a protocol, or a hypothetical public API. Do not deploy automated `premierliga.ru` crawlers or renderers unless the league grants explicit relevant permission. This restriction does not establish the terms of the separate RFU website; assess each domain on its own.

A numeric accuracy leaderboard is **not yet justified**. For each eligible source and relevant time window, compare matches against date-versioned primary evidence, recording `n_compared`, `n_missing`, `n_wrong_score`, `n_reversed_home_away`, `n_wrong_status`, `n_wrong_kickoff`, `n_late_corrections`, source revision and observed update latency. Report denominators and uncertainty, not an unsupported percentage. Accuracy must be **field-specific**: a source can be correct on final scores but unusable for as-of pre-kickoff injuries or historical line-ups.

**Multi-source resolution algorithm (not activated at M0):**
1. Only access permitted free endpoints/files within documented quotas; preserve unmodified revision/hash, retrieval and original publication timestamps (if available).
2. Normalize source match identities, competition/season, exact team and home/away roles, kickoff, status and match events. Quarantine ambiguous ID links, canceled/postponed games and incompatible scoring rules.
3. Establish a **provenance graph**: publisher → upstream provider → official primary document. Three mirrors copying the same feed do **not** count as three independent confirmations. Track unresolved upstream dependency as `UNKNOWN`.
4. For official formal match facts, prefer the relevant **dated RFU/RPL protocol or corrected official decision** over editorial aggregates. If official sources themselves conflict, quarantine and record competing timestamps rather than majority vote or silently picking the newest source.
5. For non-official observations, select a provider **per field** based on *measured* error rates, available match count, independent corroboration, coverage, freshness and permissions. Missing is not zero, and discrepancies stay visible with original provenance.
6. Enforce strict pre-match temporal cutoff for backtests. Present-day snapshots cannot be labeled as evidence of what was known before an old kickoff. Retroactive corrections may resolve **evaluation labels**, never leak backward into original forecasting features.
7. Keep a visible source/attribution ledger wherever required (especially SportScore's "Powered by SportScore" dofollow link on any page using its API). Never republish unapproved raw data or train on unapproved provider records.

**Practical priority:** inspect and rights-review Footbolno and OpenFootball as historical candidates, pursue both legitimate $0 current-fixture APIs for complementary observations, and retain the official/manual references for independent checking. All are useful within their legal scope; "all available" does **not** authorize prohibited crawling, bot evasion, premium upgrades or rights assumptions.

## Local match-by-match independent reference gate (M0)

`scripts/m0-fixture-reconcile.mjs` compares **each** Football.TXT fixture against a second, independently and lawfully obtained **local JSON Lines** reference file. It accepts exactly two local filenames and never retrieves external data or writes to Supabase:

```sh
node scripts/m0-fixture-reconcile.mjs /path/to/pinned-season_ru1.txt /path/to/independent-season.jsonl
```

Reference records must provide the *full* season's unique directed fixtures, one JSON object per line, with exact team names mapped **manually and transparently** to the Football.TXT spelling (no hidden fuzzy matching or auto-corrections). Minimal synthetic shape, **not an actual match**:

```json
{"date":"2027-01-01","home":"A Club","away":"B Club","homeGoals":1,"awayGoals":0,"resultType":"played"}
```

`resultType` is `played` or `awarded`; `date` is an ISO calendar date, **not** publication time or a timezone-aware kickoff. The comparator rejects missing/duplicate directed pairs, malformed references, conflicting scores, award flags, calendar dates and invalid/unanchored/weekday-contradictory Football.TXT dates. It includes the earlier round and fixture-structure quality gate and reports both file **SHA-256 hashes**, exact mismatch locations and a machine-readable `comparisonPassed` indicator. Exit codes: 0 for mechanically matched, 1 for mismatch, 2 for invocation/read failure. Unit tests are **synthetic only**.

**Independent provenance is not something code can infer from agreement:** record the actual second provider, license, extraction authorization, retrieved timestamp, original provider record IDs, the raw-reference SHA-256 and every explicit club-name mapping *outside this repository* before relying on a comparison. `comparisonPassed=true` expressly implies **neither** verified independence, legal clearance, strict pre-match `as_of` snapshots nor permission to import the files. For the quarantined 2023/24 season, do not silently reverse/repair the two Sochi/Spartak entries; the raw-source error must remain visible until independently resolved and an authorized correction is versioned.
