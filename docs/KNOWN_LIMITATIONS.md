# Known limitations - M0

- The public, anonymous read-only prototype is deployed to Vercel Hobby in Frankfurt. GitHub-hosted HTTP smoke verified the live site and server-side Supabase REST read. **Real owner-observed Russian wired/home no-VPN access is now verified on one network** (2026-10-22: health, dashboard, archive all HTTP 200; 130/368/333 ms). It does not prove reachability from other fixed-line ISPs. **Mobile access without VPN failed** on T-Mobile (St Petersburg, primarily T2) and MegaFon. The owner accepts this mobile limitation as **non-blocking for M0**, without diagnosing its root cause or calling those failures PASS. No commercial hosting is approved.
- Supabase Free PostgreSQL 17.11 in Frankfurt has four applied migrations (`0001`-`0004`, last tracked version `20261023081004_match_status_scores_m0`) and nine RLS tables. Six are anonymous SELECT-only; source rights, raw records and access grants remain private. The real database is empty, so there are no licensed RPL matches, model results or forecasts.
- On 2026-10-20, the same [read-only nine-table anonymous privilege/RLS catalog attestation](../database/tests/0005_live_anon_posture.sql) was executed against **live** PostgreSQL 17.11: PASS, 9 exact tables, 0 grant/policy mismatches, 0 anonymous write policies and 0 anonymous-callable SECURITY DEFINER functions. This proves live SQL catalog posture and is also required on disposable PG17 CI. A **separate real live PostgREST proof** PASSED on 2026-10-22 ([run #39763464499](https://github.com/StanleyLl0yd/FootballForecast/actions/runs/39763464499)); neither probe proves real external encrypted backup or recovery.
- On 2026-10-20, a separate production-safe [live immutable archive DDL attestation](../database/tests/0006_live_immutable_ledger.sql) returned PASS against actual Frankfurt PostgreSQL 17: **five enabled exact-operation triggers**, all bound to the expected function names **and SHA/MD5-equivalent original source bodies**, four valid/ready match lookup indexes and exactly one private authorization helper with no anonymous execution privilege. The same SELECT-only query is now required in disposable PG17 CI. This is a **catalog and function-source check**, not proof of what will happen if real provider rows or valid live published forecasts are mutated; those remain prohibited without a controlled test plan.
- **Owner-accepted recovery limitation (2026-10-22):** source-controlled application migrations `0001`-`0004` and non-secret deployment configuration are sufficient for the reduced M0 recovery gate. Exact-main [CI #39764646186](https://github.com/StanleyLl0yd/FootballForecast/actions/runs/39764646186) PASS covers `0001`-`0003`; later [exact-main CI #39921230299](https://github.com/StanleyLl0yd/FootballForecast/actions/runs/39921230299) verifies `0004` and a synthetic PostgreSQL 17 restore; this is **not recovery of real data or all Supabase services**. Live read-only check confirms zero `ff_matches`, `ff_forecasts`, `ff_source_records` and `ff_access_grants` rows. A total live-DB loss is still possible and is explicitly accepted until reconsideration once the project is fully functional (#96).
- The disposable PostgreSQL 17 restore now tests **SHA-256-pinned age v1.3.2 encryption**, rejects altered ciphertext, transfers only ciphertext between containers, decrypts in the second container and verifies the exact restored schema and synthetic rows. The one-time encryption private key lives solely on the CI runner; **no real Supabase export, owner-held offline key, offsite storage/readback or independent disaster recovery has yet been tested**.
- Automated CI now starts **real PostgREST v14.14** on the same disposable PostgreSQL 17 fixture and sends eight HTTP operations under the `anon` role: one permitted SELECT, three denied private reads, and four denied writes. The test uses an isolated unprivileged login and automatic transaction rollbacks, with no live Supabase key or production HTTP connection. This is isolated CI evidence; independently, [real live Supabase publishable-key HTTP proof #39763464499](https://github.com/StanleyLl0yd/FootballForecast/actions/runs/39763464499) also PASSED one anonymous public read and seven refused operations. Neither is real backup/recovery.
- Reproducible npm lockfile and `npm ci`, GitHub CI/Security/CodeQL, disposable PostgreSQL RLS tests, Node HTTP tests, and headless Chrome smoke pass. Headless Safari, Firefox and Edge have passed automated diagnostics, but only one Russian wired/home browser/network is confirmed; two St Petersburg mobile networks fail. Actual Supabase Free PostgreSQL 17 backup/restore and optional owner OAuth lifecycle tests are not demonstrated. **Owner explicitly waived production backup/restore as an M0/M1 gate on 2026-10-22**; review only after the product is fully functional (#96). The synthetic dump is restored to a **separate** PostgreSQL 17 container within one CI runner.
- Accounts are intentionally deferred. The optional owner-only OAuth route remains fail-closed and administrative mutations are disabled. Do not require owner login for ordinary public pages or claim operational admin access.
- Python Poisson primitives accept input intensities but have not learned strengths, been calibrated or passed real historical backtests. Data sources lack final rights approval: **no scraping, import, paid feed or fabricated fixtures**.
- A **one-time research-only** bounded Footbolno RPL CSV observation on 2026-10-20 found a *source-reported* 2026/27 schedule of 240 matches (88 marked finished, 152 scheduled). Five earlier seasons (2016/17-2020/21) have source structural anomalies and are explicitly quarantined. Current-season availability is NOT independent match correctness, a right to import/train, or historical as-of timestamp evidence. Raw provider rows remain outside Git/Supabase; see `docs/M0_FOOTBOLNO_RPL_AGGREGATE_EVIDENCE.json`.
- The owner reduced the mandatory historical source horizon on 2026-10-20 to **2024/25 training, 2025/26 untouched test, 2026/27 current fixtures** (see `docs/M0_MINIMUM_RPL_SCOPE.json`). This makes only a fixed Poisson pilot *potentially* evaluable; it is not enough for independent calibration/hyperparameter tuning. Full 2015/16–2023/24 history is optional, and all three pilot seasons remain unlicensed/unverified for ingestion.
- Evaluation and model contracts are partial; filters, detailed match predictions, independently validated charts and user profiles are not yet implemented. Publication/temporal-integrity guards are in SQL, but a functioning authorized prediction worker remains future work; a production backup decision is deferred to a fully functional project (#96).
- An **owner-accepted, narrowly scoped dev-only residual risk** (2026-10-22) remains in transitive ESLint dependency `braces@3.0.3` (GHSA-vfj7-8cjw-p6xm), tracked by non-gating issue #8. No fixed version has been confirmed: this is **not a vulnerability remediation** and it has **not** been proven that every future build/deployment excludes it. Protected CI runs `npm audit --omit=dev --audit-level=high` and a fail-closed full audit allowing only the verified all-`dev:true` ESLint propagation chain. Any other HIGH/CRITICAL finding, altered risk identity/chain, or production exposure fails the gate and requires re-evaluation. Dependabot remains active to remove the exception when a vetted patch arrives. This accepted risk no longer blocks M0. CSP hardening and external security review remain open.
- Vercel deployment status and canary success do not establish availability under Russian operator filtering, future scalability or legality of storage/processing for possible future Russian user accounts.

M0 remains OPEN. M1 may not start until the owner accepts M0.

- Optional OAuth token refresh is scoped to administrator requests; ordinary visitors do not need an auth session. Real owner OAuth E2E remains deferred.

- Public archive now queries the last 20 immutable predictions with timestamp, model, hash and 1X2 probabilities; evaluation charts, match details, source rights and actual historical forecasts remain missing. The real archive has zero records until a licensed pipeline exists.

- Cross-browser CI success does not prove availability across all Russian residential/mobile networks. One actual no-VPN wired/home observation passed 3/3 and two actual mobile observations failed to load the site. Under the 2026-10-22 owner-approved M0 scope, wired success is sufficient for the prototype, and mobile diagnostics are deferred, non-gating (#6).
